# Безопасность репозитория

Репозиторий временно открыт, чтобы пользоваться бесплатными минутами GitHub
Actions для публичных проектов. В конце месяца возвращается в приватный.

## Что НЕ лежит в коде

Все рабочие значения живут в GitHub Secrets и в файлах на сервере, не в git:

- `BOT_TOKEN` / `STAGING_BOT_TOKEN` — токены Telegram-ботов
- `VPS_DEPLOY_SSH_KEY` / `VPS_STAGING_DEPLOY_SSH_KEY` — ключи деплоя
- `VPS_HOST` — адрес сервера
- `STAGING_CLONE_TOKEN`, `CLAUDE_CODE_OAUTH_TOKEN`, `NOTIFY_CHAT_ID`
- Robokassa: `merchant_login`, `password_1`, `password_2` — только через `.env` на сервере
- Ключ сервисного аккаунта Google Sheets — файл на сервере, каталог `secrets/` в `.gitignore`

Все пароли/логины, встречающиеся в коде и тестах (`pullup:pullup`, `shop`,
`pass1`, `123456789:AAFake...`) — заведомые заглушки для локальной разработки
и тестов, не рабочие значения.

## Защита от посторонних запусков

`\.github/workflows/claude\.yml` запускает платного агента только для владельца
репозитория (`author_association == 'OWNER'`). Без этого любой человек мог бы
открыть issue с упоминанием агента и жечь чужую подписку.

Workflow'ы деплоя запускаются только вручную (`workflow_dispatch`), доступно
только тем, у кого есть write-доступ.

SSH-ключи деплоя заперты forced-command обёрткой в `authorized_keys`: через них
нельзя выполнить произвольную команду, только `./deploy.sh <sha>` или
`./deploy-staging.sh <branch>`.

## Что известно и принято осознанно

- **Адрес сервера остаётся в истории коммитов.** Переписывать историю ради
  этого не стали: адрес и так виден через DNS (`app.bimoool.com`), а SSH
  защищён не скрытностью адреса, а forced-command и ключами.
- **Контактная почта поддержки** в текстах бота — публична по назначению,
  её видят пользователи бота.

## Если нашли проблему

Напишите владельцу репозитория напрямую, не открывайте публичный issue.
