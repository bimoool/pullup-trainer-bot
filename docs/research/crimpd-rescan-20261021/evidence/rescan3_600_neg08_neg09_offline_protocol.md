# Протокол NEG-08/NEG-09 и офлайн (Crimpd 8.5.3, 2026-10-24; тестовая тренировка «RESCAN3 TEST WO», Back Squat 2×1, rep 5 с; сущность T2-013)
Водитель: селекторы + проверка экрана; тапы по координатам — только по актуальному скриншоту.

## NEG-08 блокировка занятия (область: Start у тренировки)
Действия подряд в один день: Start Workout на «RESCAN3 TEST WO» (не менее 5 запусков за прогон, в том числе при активной сессии другой тренировки и повторно после сохранённого лога). Результат: «Start Workout» всегда доступна, предупреждений о недавней тренировке/отдыхе нет, лог от даты сегодня не блокирует повторный старт. Вывод: блокировки следующего занятия в проверенной области (кнопка Start у отдельной тренировки) нет. НЕ проверено: блокировка внутри активного плана (в плане владельца нельзя создавать записи; тестовый план с занятием на сегодня создаётся — см. R02, но ограничение «один активный план» и пересечение с планом владельца мешают активировать второй; условие — тестовый аккаунт).

## NEG-09 восстановление сессии
| Сценарий | До | Действие | После |
|---|---|---|---|
| Фон 25 с | сессия: set 1/2 → rest, вес 3 кг в панели | HOME, 25 с, возврат | сессия жива, таймер шёл по часам (set 2/2 «GO!» 00:07), введённый вес 3 кг сохранён в Log-листе (rescan3 bg) |
| Свёрнуть chevron | идёт сессия | кнопка ˅ | страница тренировки + мини-плеер «Set 1/2 · Rep 1/1 GET READY 00:04» с паузой и ✕ |
| Смахивание из недавних | сессия set 1/2 → 2/2 | Recents → смахнуть карточку Crimpd | процесс завершён (pidof пусто); при запуске — Home; незавершённая сессия НЕ предложена, лог НЕ создан («You have not logged this workout…») |
| force-stop | сессия GET READY 1/2 | `am force-stop` | Home, продолжения нет, лога нет |
| Новый Start при активной | активна сессия (Back Squat) | открыть другую тренировку, Start | открывается новая сессия с нуля (UP NEXT 1/2); прежняя заменена без вопроса (воспроизводит OBS-0101) |
Ограничение: при «смахивании» эмулятор убивает процесс — на реальном телефоне поведение фоновых сервисов (notification permission denied) может отличаться.

## Офлайн (airplane mode: `cmd connectivity airplane-mode enable`)
| Сценарий | Результат (наблюдаемое) | Предполагаемая причина |
|---|---|---|
| A. Сеть пропала до Save; Save | кнопка показывает спиннер ~3–8 с, затем форма возвращается с введёнными значениями (3 кг), текст ошибки на скриншотах 1/3/8/15 с не виден; запись не создана | запрос завершился ошибкой сети (INFERRED; тост мог исчезнуть между выборками) |
| B. Сеть возвращена (airplane off) и 50 с ожидания без действий | форма остаётся открытой, лог НЕ отправлен автоматически; после закрытия формы «You have not logged this workout…» | очереди повторной отправки нет (INFERRED по отсутствию записи) |
| C. Повтор после восстановления сети | форму закрыл, открыл заново (поля сброшены к 0 — введённое при офлайне не сохраняется), ввод повторил как новую запись — см. D; отдельной одиночной записи онлайн для сравнения не создавал | — |
| D. Двойной Save | ДВА тап в одном вызове adb (`input tap …; input tap …`, интервал ≈десятки мс) → две идентичные записи 10:35 (rescan3_610_double_save_two_cards.png). Ранее два тапа отдельными вызовами (~0.3 с) дубликата не дали (rescan3_430). Вывод: дубль воспроизводится при почти одновременных нажатиях; при интервале ~0.3 с не воспроизведён | нет блокировки повторной отправки (INFERRED) |
Сценарий «сеть пропала во время отправки» (между тапом и ответом): при ручном нажатии интервал неуправляем; разделить «до» и «во время» не удалось — условие: прокси/сетевой шейпер с задержкой ответа.
