## Воспроизводимые сценарии для заблокированных проверок (готовы к запуску при появлении входа)
Общее условие: любая разрешённая среда с тестовыми данными и входом в Crimpd на `test_pixel6_play`/в вебе, где допустимы изменения; перед каждым — baseline по `future-test-rules.md`.
- **Q07 Time Zone:** зафиксировать время 2 тестовых логов и границу недели → сменить Time Zone в Settings (соседняя зона со сдвигом ≥6 ч) → сверить время логов в Logbook, недельные разбивки Analytics → вернуть зону → сверить снова → холодный перезапуск.
- **Q08 Grade System:** записать три значения грейда в текущей системе → переключить Hueco↔Font / French↔YDS → зафиксировать пересчитанные значения и «Target grade» тренировок → вернуть систему → сравнить с baseline (округление туда-обратно).
- **Q10:** активный план с назначенным занятием на сегодня → попытаться открыть/залогировать занятие, блокируемое планом → состояние плана и логов до/после снятия.
- **Q11:** `adb shell settings put global auto_time 0` + смена даты/пояса устройства на +1 день и −1 день → Today/Plans/Logbook/Analytics → возврат даты (на тестовом эмуляторе).
- **Q12:** тестовый вход + `adb emu network delay umts`/`speed gsm`, режим «в самолёте» ровно в момент нажатия Save на форме лога → ожидание: нет записи / одна / две; сообщение пользователю; повтор Save.
- **Q13:** (1) создать результат Finger Strength Test +X → зафиксировать назначения Max Hangs A/B/C → правка результата → удаление → после каждого шага: назначения, Profile, Test History, Analytics, перезапуск, повторный вход. Ожидание формулы: A/B/C = 85/90/95% × (вес тела + результат) − вес тела.
