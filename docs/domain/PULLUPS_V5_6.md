# PULLUPS_V5_6 — основная программа «Подтягивания» V5.6 (канонический контракт)

**Источник истины** — документ владельца «Программа V5.6: авторегуляция внутри фиксированной
структуры» (11.10.2026). Этот файл фиксирует, как он реализован (issue #305): что считается, где лежит,
какие места оставлены явным швом. При расхождении прав документ владельца, а не этот файл и не общие
представления о тренировках.

**Решение владельца V5.6 заменяет прежнее решение OD-3 «прогрессию двигает только подход на максимум»**
(#305, `cc4aa65`). Универсального «MAX двигает прогрессию» больше нет: у каждого блока свой сигнал.
Прежняя история решения сохранена в `PROGRAM_PLAN_V2.md` §11 как контекст устаревшей версии.

Код: чистый домен `app/domain/pullups_v5.py` (без aiogram/SQLAlchemy, вес — `Decimal`), оркестрация
`app/services/course_v5.py`, HTTP `app/web/routes_v2_course.py`. Золотые тесты — `tests/test_pullups_v5.py`
(каждый пример документа владельца с точными числами), API — `tests/test_web/test_v2_course_v5.py`.

## 1. Версии программы

| `program_version` | Где | Исполнение |
|---|---|---|
| `pullups_v5_6` | `progression_state.program_version` новых инклюзий; правило `pullups_v5_6@1` (`decided = true`) | этот контракт |
| `pullups_legacy_step` | состояние без `program_version` (`block_a`/`block_b` бот-эпохи); правило `program_config_default@0` | прежний код: рабочие подходы + подход на максимум, `StepProgressionStrategy` (`session_log._apply_step_progression`) |

* Новая инклюзия — V5.6 по умолчанию. Устаревшая — только явно: `program_version: "pullups_legacy_step"` или
  прежние поля `initial_target_a/b` (они описывают состояние устаревшей версии). `pullups_v5_6` вместе с
  `initial_target_*` — 422.
* **Активные инклюзии устаревшей версии в V5.6 не переводятся** (нет детерминированного соответствия
  «цель + подходы бот-эпохи» → уровень/R/1RM V5.6). Они продолжают исполняться прежним кодом. Переход —
  явное решение пользователя/владельца: снять курс и подключить заново (`restart: true`) с входами V5.6.
  Это шов раскатки, см. §13.

## 2. Структура занятия

Две основные тренировки в неделю, **A** и **B**, по последовательности (не по календарю):
`state.next_role` чередуется после каждого завершённого основного занятия, роль занятия фиксируется в его
снимке. В каждой: разминка → объёмный блок → 15 минут → подводка к рабочему сопротивлению → силовой блок.

| Отдых | Значение |
|---|---|
| A, объём, между подходами | 240 с |
| B, объём, между подходами | 30 с (от конца подхода до начала следующего; в программе не варьируется) |
| объём → сила | 900 с |
| сила (оба уровня), между подходами | 180 с |
| тест 1RM, между подходами | 180 с |

Эти значения — часть выданного рецепта (снимка), не таймера движка v1 (§11).

## 3. Входы (§3 документа)

`M` — свежий максимум строгих подтягиваний без веса (из ввода, иначе из валидного замера: результат протокола
программы или замер онбординга). `R` — расчётный максимум в ТЕКУЩЕМ варианте объёмного движения: на уровне 1 —
способность с объёмной резиной, калиброванной на ≈8–12 строгих повторений (правило калибровки продукта, не
физиологический порог); с массой тела — `R = M`. `BW` — масса тела (профиль, `User.weight_kg`; обновляется раз
в неделю и переносится во входы только вперёд). `E1RM` — максимальный ДОПОЛНИТЕЛЬНЫЙ вес на одно строгое
повторение, из M не выводится. Подтверждённая история (`known_a_targets`, `known_volume`,
`known_strength_a/b_kg`) сильнее стартовых формул. Шаг дополнительного веса — `load_step_kg` (ввод
оборудования; глобального инвентаря нет).

Недостающий вход ничего не подставляет: `pending_inputs` следующего занятия, старт main — **409**
`{code: "course_setup_required", missing: [...]}`, Dashboard — `status = course_setup_required`.

## 4. Уровни

| Уровень | Когда | Объём | Сила |
|---|---|---|---|
| `assisted` (уровень 1) | M < 10 | с резиной (R по резине) | A и B одинаково: `5/5/5/5/5–8`, помощь |
| `transition` | допуск получен внутри программы ИЛИ стартовый M = 10–14 | без резины: A `5/5/5/5+`, B `10×3` | A `5×5`, B `5×3` с весом |
| `weighted` (уровень 2) | стартовый M ≥ 15; или выход из переходной лестницы B (закрыт `10×5`) | стандартные формулы | A `5×5`, B `5×3` с весом |

Допуск к весу — два равноправных продуктовых сигнала (не биологические пороги): свежий M ≥ 10 на старте;
внутри программы `5/5/5/5/8` с массой тела, отдыхом 180 с и подтверждённой техникой. При допуске резина
убирается из объёма, начинается переходная неделя, силовые блоки ждут 1RM (отдельный свежий день).

## 5. A — длинный объём

* Старт без истории: `a = min(20, max(3, floor(0,70 × R)))`, план `a/a/a/a+`. Потолок 20 — только старт.
* Последний подход — технический AMRAP (строго, без неудачной попытки, киппинга, отдыха на одной руке,
  отпускания хвата; минимальная цель `p4`). `VA_fact = факт1+…+факт4`. Результат AMRAP **не** свежий M.
* Зелёный: первые три закрыты, последний ≥ `p4+2`, техника подтверждена → +1 обязательное повторение
  ВСЕГО, в подход с наименьшей целью, при равенстве — в самый ранний (`18/18/18/18+ → 19/18/18/18+ → …`).
* Жёлтый (`p4` или `p4+1`) и красный (любая цель не закрыта) — план повторяется. Запас +2 без
  подтверждённой техники — повтор (`unconfirmed`).
* Два красных подряд — откат последнего добавленного повторения (стек `additions` делает откат
  детерминированным). Откатывать нечего — намерение `increase_assistance` (резина — по личному порядку,
  иначе выбор пользователя; конкретная резина не угадывается).

## 6. B — короткий объём

* Старт: `V_ref` — подтверждённый объём (`known_volume`) или факт первой A. `S = min(20, max(10, floor(V_ref/5)+1))`,
  `q = 5`; при `V_ref ≥ 100` — `S = 20`, `q = floor(V_ref/20)+1`. Примеры: 30 → `10×5`, 70 → `15×5`, 100 → `20×6`.
* Исполнение: каждый подход пишет факт; 3 повторения — продолжать; ≤ 2 — подход засчитывается в `VB_fact`
  и блок заканчивается; также по нарушению техники и после S подходов. Максимального подхода в B нет.
* Прогрессия — только при полном закрытии `S×q` с подтверждёнными техникой и отдыхом 30 с:
  `S < 20 → (S+1)×q`; `S = 20 → 20×(q+1)`. Иначе S и q не меняются; следующее занятие показывает
  промежуточную цель `прошлый VB_fact + 1` — только отображение, ступень она не открывает.
* Переходная лестница: `10×3 → 10×4 → 10×5 → 11×5 → …` (закрытие `10×5` переводит уровень в `weighted`).

## 7. Сила уровня 1 — `5/5/5/5/5–8`

Первые четыре — ровно по 5; пятый — контрольный (минимум 5, жёсткий потолок 8, неудачная попытка не
нужна; факт выше 8 считается как 8). У A и B — своя помощь (следующая одноимённая тренировка):

| Результат | Намерение |
|---|---|
| первые четыре закрыты и пятый = 8 (техника подтверждена) | `decrease_assistance` на одну доступную ступень |
| пятый 5–7 | `keep_assistance` |
| недобор в первых четырёх или пятый < 5 | `increase_assistance` |
| `5/5/5/5/8` с массой тела, отдых 180 с подтверждён | допуск к весу |

## 8. Помощь и оборудование

* Запись помощи однозначна: `kind` (`band`/`bodyweight`), `equipment_item_id`/название, цвет, крепление,
  положение стопы/колена. Килограммы резине не приписываются.
* «Одна доступная ступень» — по ЛИЧНОМУ упорядоченному списку резин (`EquipmentItem.position`, 0 — больше всего
  помощи). После самой лёгкой — масса тела. Нет списка или следующей ступени — `assistance_selection` в
  состоянии, старт ждёт выбора пользователя (`PUT …/course/inputs`), текущая помощь сохраняется как есть.
* Новой резине из списка известны только id/название; крепление и положение подтверждает пользователь (шов).

## 9. Сила уровня 2 — `5×5` (A) и `5×3` (B)

* Вход по приоритету: недавний подтверждённый `5×5`/`5×3` → стандартизированный 1RM → (до допуска — уровень 1).
* `T1RM = BW + E1RM`; `E5 = вниз до шага (0,75·T1RM − BW)`, `E3 = вниз до шага (0,80·T1RM − BW)`; ≤ 0 — масса
  тела (без помощи, пока план не провален). 75/80 — консервативная формула продукта.
* Прибавка (A и B независимо): `Δraw = 0,02 × (BW + Ework)`; `Δ` — ближайший доступный шаг (кратный
  `load_step_kg`) в пределах 0,5–2,5 кг, при равенстве меньший; нет шага в пределах — прибавки нет
  (`load_increment_unavailable`). Примеры: 70/10 при шаге 0,5 → +1,5; 80/40 → +2,5; 95/60 → +2,5.
* Все повторения закрыты, техника и отдых ≤ 180 с подтверждены → следующий одноимённый день `E + Δ`.
  Любой недобор — тот же вес. Лишние повторения не ускоряют (в расчёт идёт не больше цели).
* Плато (§8.6): сумма повторений растёт — ждём; 1–2 одинаковых неполных — вес тот же; 3 сопоставимых
  неполных без улучшения или 2 ухудшения подряд — калибровка: отмена ТОЛЬКО последней прибавки, схема
  сохраняется. Снова 3 попытки без прогресса (или отменять нечего) — предложение свежего 1RM либо
  калибровки снизу; новый 1RM не обязателен, вес сам не меняется.

## 10. Тест 1RM

Отдельный свежий день, не после объёма, не раньше 48 ч после тяжёлой тяговой работы (409
`one_rep_max_too_soon`). Не больше 8 подходов: BW×5 → +10% BW ×3 → +20% BW ×1 → одиночные с прибавкой
≈10/5/2,5% BW после быстрого/обычного/медленного повторения, проценты вниз до шага. Стоп после первой
неудачной попытки; результат — последний успешный дополнительный вес; успешный и не медленный восьмой —
консервативный максимум (девятого нет). Реализация: если округление прибавки вниз даёт 0, берётся один шаг
(иначе попытка повторяла бы тот же вес). 2RM не используется. Более крупные первые шаги для опытных —
не реализованы (шов). Ведение теста — `POST …/one-rep-max/next-set`; запись — `POST …/one-rep-max`
(факт в `state.one_rm_tests`, E1RM заполняет ожидающие веса вперёд).

## 11. Техника и отдых

Определить технику автоматически нельзя. Пользователь подтверждает по блоку: `session_blocks.technique_valid`
и `rest_within_limit` (nullable, миграция `b5d8e1f3a6c9`), передаются в `POST /sessions/live/{id}/complete`
(`block_checks`). **NULL — неизвестно и никогда не «валидно»** для правил, которые требуют техники
(зелёный A, закрытие B, уменьшение помощи, допуск, прибавка веса) или отдыха (B, допуск, прибавка веса).
Компьютерной оценки нет. Подтверждение рисует движок #306 (шов, §13).

## 12. Снимок рецепта, история, только вперёд

Рецепт занятия пишется **один раз** при живом старте в `prescription_snapshot` (S1):
`provenance.course_program` — версия, уровень, роль A/B, структура, блоки (роль блока, подходы с целями,
маркеры `working`/`amrap`/`control`/`dynamic`, потолок 8, отдых каждого подхода, помощь, внешний вес,
стоп-правило B, промежуточная цель, ступень переходной лестницы), 900 с между блоками, входы расчёта
(M, R, BW, E1RM, шаг, известные результаты, V_ref, допуск); `provenance.strategy = pullups_v5_6`,
`progression_state_rev`; в стандартных полях снимка — `rest_after_seconds` подходов и
`rest_after_block_seconds = 900`. SetTarget: AMRAP — `is_max_set` с минимальной целью `p4` в `value`;
прогрессия читает факт по позиции и тип блока из рецепта, а не флаг.

Прогрессия считается один раз — при завершении основного занятия, из рецепта СНИМКА этой сессии и её факта
(`advance_session`); результат типизирован по блокам (`a_volume`, `b_volume`, `assisted_strength`,
`a_weighted_strength`, `b_weighted_strength`). Правка истории (#307) меняет факт, но не состояние, не снимки,
не SetTarget и не занятия плана; каскадный реплей (`/progression/{preview,apply}`) к V5.6 неприменим (422).
Повторное завершение — без второй прогрессии; копия сессии — ручной повтор без кредита и прогрессии.
Целиковая запись `POST /sessions` рецепта не несёт — `v5_requires_prescribed_session`, прогрессии нет.

§9 документа: два занятия подряд с одновременным ухудшением обоих блоков (только при том же плане) —
`recovery_check_required`, новые прибавки не назначаются, пока пользователь не подтвердит проверку
восстановления и внешней тяговой нагрузки (`clear_recovery_check`).

## 13. Швы (не реализовано здесь)

* **Движок #306 (Live Engine V2)** после интеграции с #306 исполняет из снимка PREP и отдых 240/30 → 900 → 180
  (явный отдых снимка важнее умолчаний движка, `app.domain.live_engine_plan.fallback_block`); подтверждения
  техники/отдыха, пришедшие с явным завершением `POST …/complete`, записываются до серверного завершения.
  **Не реализовано в движке (швы, решение владельца):** динамический стоп B (≤ 2 повторения / техника) — движок
  ведёт все S подходов, прогрессия применяет стоп-правило к факту сама; минимум `p4` AMRAP и потолок 8
  контрольного подхода движок не проверяет; подтверждения техники/отдыха, когда движок завершил тренировку сам
  (последний подход), не собираются до завершения — прогрессия видит NULL («не подтверждено»). Движок v1 этого
  не умеет и не дорабатывается: он исполняет SetTarget с прежним отдыхом.
* **UX входов**: минимальная форма недостающих входов на пред-экране есть (`CourseSetupForm`); нет — пошагового
  ведения теста 1RM (API `next-set` есть), выбора следующей резины из личного списка, подтверждения
  крепления/положения для резины, выбранной по порядку.
* **Раскатка** устаревших активных инклюзий (§1) — решение владельца, не автоматический перевод.
* Внешняя тяговая нагрузка (кроссфит, выходы силой) записывается как история; сопоставимость попыток
  плато по ней не уточняется. Факультативы V5.6 не реализуются.
* Свежий контрольный M раз в 4–6 недель — показатель результата, состояние программы не меняет.
