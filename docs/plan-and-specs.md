# Турникмэн → «Crimpd для турника». Аудит и план для чата-навигатора

*Составлено 19 сентября 2026 по: референсу Crimpd (60 скринов + разбор APK), паспорту проекта, архитектурному документу `turnikmen-multicourse-architecture.md` и переписке с Кириллом.*

Цель: приложение, **идентичное Crimpd по навигации и фронтенду**, с нашей начинкой (подтягивания с прогрессией, геймификация, бот, подписка). Сначала Mini App, потом PWA.

---

## 1. Где мы на самом деле

Волны 0–4 сделаны и лежат в `feature/multi-program`. Это большой фундамент: интерфейс прогрессии, новая схема, бэкфилл, `/api/v2`, Dashboard. PR #171 — первый раз, когда всё это прошло через CI. Волна 4 ждёт визуальной приёмки на staging.

Дальше — волны 5–11. Именно там начинается «сделать как Crimpd»: экран сессии, каталог, план по неделям, история.

Что важно понимать: **фундамент строился до того, как мы договорились «навигация — как в Crimpd»**. Поэтому часть сделанного надо не переделывать, а переставить по местам (см. ошибку №1).

## 2. Аудит: расхождения и ошибки

Это то, что при передаче агентам даст расхождение между документами, если не поправить. Отсортировано по цене исправления.

### №1. Стартовый экран — не «Dashboard», а Home-каталог ← самое важное

В архитектурном документе стартовый экран — «Dashboard: единый план, что осталось на неделе». В Crimpd стартовый экран — **Home = каталог тренировок с поиском**, а план живёт во вкладке **Training Plans**. Раз мы делаем навигацию идентичной, Dashboard из волны 4 надо **не выбрасывать, а перенести**: его содержимое — это вкладка «Training Plans → In Progress», а не Home.

Что делать: пять вкладок как в Crimpd — **Главная / Планы / Журнал / Аналитика / Профиль**. На Главной — каталог + блок «Мои тренировки» + «Избранное» + «Тесты» (ровно как в Crimpd). Виджет «осталось на неделе» — небольшой блок наверху Главной, не весь экран.

### №2. XP — не новая валюта, а существующие монеты

В архитектурном документе заведены `XP`/уровень как новая сущность. В коде **уже есть монеты и достижения** с реестром триггеров. Две параллельные валюты — классический источник багов и путаницы для пользователя. XP = монеты, уровень = функция от суммы монет. Волна 8 — обобщение, не новая система (паспорт это уже фиксирует, документ — нет).

### №3. Серверные таймеры уже есть — риск «фонового таймера» решён наполовину

Документ ставит фоновый таймер как нерешённый риск. В проде **уже есть серверные таймеры, переживающие падение Telegram**. Значит клиент должен считать время от серверного `ends_at`, а не заводить свой отсчёт. Остаётся только UX-часть: Wake Lock (чтобы экран не гас) и предзапланированный звук. Волна 5a становится меньше.

### №4. Recharts — нет. Свои SVG-графики — уже решение проекта

Я рекомендовал Recharts. В проекте **осознанно** сделаны SVG-графики без библиотек. Не добавлять зависимость ради того, что уже работает. Расширять свои.

### №5. Видео на этом VPS — нельзя

Сервер: 1 vCPU / 1 GB, и на нём живёт второй проект. Хранить и раздавать видео с него, тем более транскодировать — сломает оба. Правильно: **внешнее S3-совместимое хранилище** (Selectel/Yandex Object Storage для российской аудитории, или любой S3), видео **готовятся офлайн в HLS** — Кирилл видеопродакшн, ffmpeg-пайплайн у него есть, — и заливаются готовыми. Сервер только хранит ссылки.

### №6. Минуты GitHub Actions — процесс, а не код

2000 минут сгорели за 19 дней, репозиторий временно публичный, **в начале октября вернуть в приватный**. Основной расход — облачный агент (5–20 минут за запуск). Пока репозиторий публичный, минуты бесплатны, но октябрь настанет. Решение на уровне процесса: тяжёлые волны запускать через **локальный Claude Code на машине Кирилла**, а не облачного агента; тесты гонять в песочнице Claude (минута, минут Actions не тратит); облачного агента оставить на мелкие правки и ревью.

### №7. Модель агента не закреплена

Договорённость «Sonnet по умолчанию, Opus на тяжёлые волны» есть, в `claude.yml` — нет. Одна строка `model:` в `claude_args`. Сделать до волны 5.

### №8. `ROADMAP_tm.md` — читать нельзя

Вебхуки, ветка ASSISTED, лимит 7 дней, старые названия блоков — всё устарело. Агент, который его прочитает, унесёт в код мёртвые сущности. Либо удалить, либо заменить на ссылку на паспорт.

### №9. Мелочи, которые всплывут

- Факультативы (`elective_workouts`) сливаются в общую историю в волне 1 — проверить, что это действительно случилось в миграции, а не отложилось.
- Правило «выбрал день — соседние заблокированы» — переиспользуемое, не только для подтягиваний. Должно быть в `rest_policy`, не в коде подтягиваний.
- `Dockerfile` не копирует `scripts/` — бэкфилл в проде запускать через `docker cp`, агент об этом не знает, если не сказать.

## 4. Готовое, чтобы не писать с нуля

Всё ниже — реальные, живые библиотеки. Никакой экзотики.

**Фронтенд**
- `@telegram-apps/sdk` + `@telegram-apps/telegram-ui` — уже в проекте. Кнопка «назад», тема, viewport — только через них, не руками.
- `@tanstack/react-query` + `@tanstack/query-sync-storage-persister` + `idb-keyval` — кэш, офлайн-очередь мутаций, ретраи, оптимистичные апдейты. Закрывает офлайн-слой волны 5 целиком; свой слой синхронизации не писать.
- `vite-plugin-pwa` — манифест + service worker (Workbox под капотом) одной секцией конфига. Волна 9.
- `@dnd-kit/core` — перетаскивание упражнений по дням в недельной матрице.
- `nosleep.js` — Wake Lock с фолбэком для iOS Safari (у которого нативный Wake Lock ограничен). Волна 5a.
- `hls.js` — воспроизведение HLS без YouTube. Волна 10.
- Графики: **свои SVG**, как есть.

**Бэкенд** — ничего нового. SQLAlchemy/Alembic/APScheduler/FastAPI уже закрывают всё.

**Открытые наработки как источник данных и идей (не форкать)**
- `yuhonas/free-exercise-db` — 800+ упражнений в JSON с картинками, свободная лицензия. Готовая заготовка для библиотеки `Exercise` — не набивать руками.
- `wger-project/wger` — открытый менеджер тренировок на Django. Смотреть модель упражнений/программ и как они делают недельные планы. Не тянуть код.
- `astashov/liftosaur` — открытое приложение с собственным языком прогрессии. Смотреть, как описаны стратегии прогрессии декларативно; полезно для конфига `Program` без хардкода констант.

**Инструменты процесса** — уже есть: `graphify` (карта кода), Playwright, GitHub Spec Kit локально.

## 7. Как ставить задачи, чтобы не получить костыль

Три правила, которые уже подтверждены болью в этом проекте:

1. **Сначала контракт, потом код.** Волна 5 — образец: скилл с контрактом офлайн-логирования пишется до первого эндпоинта. Иначе фронт и бэк разойдутся.
2. **Одна волна — один PR — один деплой на staging.** Ничего не копить. PR #171 с пятью волнами разом — не повторять.
3. **Агент не додумывает продукт.** Если в задаче нет ответа на «как это должно выглядеть» — агент смотрит `crimpd-reference`; если и там нет — останавливается и спрашивает. Это ключевое правило онбординг-документа.

## 9. Онбординг нового пользователя в новой модели

**Дефолт [подтвердить]:** пользователь никогда не попадает в пустой каталог. Первый курс подключается автоматически.

```
/start в боте
  → кнопка «Открыть приложение» (Mini App)
  → экран приветствия: 3 карточки-свайпа (что это, как работает план, что бесплатно)
  → ЗАМЕР = первый AssessmentProtocol «Подтягивания: максимум» (как сейчас, инструкция по резине)
  → анкета: вес, рост, пол, дата рождения, часовой пояс (как сейчас)
  → система создаёт TrainingPlan + ProgramInclusion(seed-программа «Подтягивания»)
  → открывается вкладка «Планы» с первым планом: «Первая тренировка доступна»
  → триал 14 дней с момента замера (как сейчас)
```

Пропуск замера невозможен (без него нет target'ов). Анкету можно «заполнить позже» — тогда лидерборд и нормативы недоступны до заполнения, план работает.

**Существующий пользователь после cutover (волна 7):** видит то же приложение, его данные уже перенесены бэкфиллом волны 2; никакого повторного онбординга. При первом входе — один экран «Что нового» с кнопкой «Понятно».

## 10. Спецификации экранов

Формат каждого: что видно · действия · состояния · чего нет в Crimpd (наше).

### 10.1 Главная (= Crimpd Home)

**Видно:** строка поиска «Что тренируем сегодня?» · виджет недели (наш): «На этой неделе: 2 из 5 · стрик 3 нед» с кнопкой «К плану» · горизонтальные секции по категориям с карточками курсов (картинка, название, N тренировок) · «Мои комплексы» (пользовательские) · «Избранное» · «Тесты» (карточки AssessmentProtocol) · плавающая «+» → меню: Свободная тренировка / Внести задним числом / Создать комплекс.
**Действия:** тап по курсу → карточка курса (10.3) · тап по тесту → экран теста · поиск → список по совпадению названия/категории.
**Состояния:** нет ни одного своего комплекса → секция скрыта, не «пусто» · нет избранного → скрыта · план отсутствует (не должно случаться после онбординга) → виджет заменяется кнопкой «Собрать план».
**Наше:** виджет недели, стрик.

### 10.2 Планы (= Crimpd Training Plans)

**Верх:** вкладки «Текущий / Завершённые». (Upcoming из Crimpd не нужен: план один и бессрочный.) **[подтвердить]**
**Текущий план — видно:** полоса недель с фазой (Base/Rest/Peak) и текущей подсвеченной · сводка недели: «сессий 5 · сделано 2 · ~2 ч» · список `PlanItem` этой недели, сгруппированный: сначала закреплённые за днями (по дням), затем «Свободный пул»; внутри комплексы свёрнуты в одну строку с раскрытием · у каждой строки: название, источник (бейдж курса или «своё»), сделано/план (1/2), кнопка «Начать» · внизу «Подключённые курсы» с прогрессом (неделя 3 из 6) и датой окончания.
**Действия:** «Начать» → пред-экран сессии (10.7) · долгий тап/иконка → перетащить на день или в пул (`dnd-kit`) · «Редактировать план» → редактор (10.4) · курс → карточка курса · «Добавить курс» → Главная.
**Состояния:** курс закончился → строка курса становится «Завершён ✓ · Выбрать следующий» · неделя прошла с невыполненным → в «Завершённые/Итоги недели» видно план vs факт, невыполненное не переносится · rest_policy жёсткая и отдых не прошёл → кнопка «Начать» у этого упражнения серая с подписью «отдых до завтра» · мягкая → кнопка активна, при нажатии предупреждение.
**Завершённые:** список закрытых курсов (название, даты, % выполнения) и итоги прошлых недель.
**Наше:** rest_policy на кнопке, источник у строки, прогресс курса.

### 10.3 Карточка курса (= Crimpd Skill Template)

**Видно:** обложка · название · одна строка сути · переключатель уровней (A/B…) если есть · иконки снаряжения · «~N ч/нед» · кнопка «Добавить в план» / «В плане ✓» · Описание · Расписание по неделям: Неделя 1 [Base] → список упражнений с кол-вом.
**Действия:** «Добавить в план» → проверка пересечений (10.5) → создаётся `ProgramInclusion` (снимок) → возврат в Планы.
**Состояния:** курс уже в плане → кнопка «В плане ✓», под ней «Удалить из плана» (с подтверждением; история сохраняется) · нет подписки и триал кончился → кнопка «Доступно по подписке» → экран подписки.

### 10.4 Редактор плана (= Crimpd plan-builder)

**Видно:** матрица «строка = упражнение/комплекс, столбец = неделя», в клетке — количество · над матрицей полоса недель с фазой (фазу можно менять тапом) · строка «Итого сессий / часов» · у строки карандаш → лист «Объём по неделям» (как в Crimpd: неделя · фаза · длительность · кол-во ±) и «Удалить из плана».
**Действия:** ± в клетке · добавить строку «+» → выбор упражнения из библиотеки или своего комплекса · сохранить.
**Правило:** редактирование строки, пришедшей из курса, не трогает снимок курса — меняется только `PlanItem`; курс остаётся «в плане».

### 10.5 Диалог пересечений

При добавлении курса: если у нового курса есть `Exercise`, который уже есть в плане на пересекающихся неделях — лист «Похожие упражнения уже в плане» со списком пар (наше / из курса, источник каждого), у каждой пары: «Оставить оба» (дефолт) / «Убрать моё» / «Не добавлять из курса». Кнопка «Готово». Ничего не сливается автоматически.

### 10.6 Журнал (= Crimpd Logbook)

**Видно:** месяц с навигацией ‹ › · календарь с точками по дням (цвет = категория) · под ним список по неделям и дням; карточка сессии: название, Интенсивность (effort), Выполнение %, Отягощение ±, время под нагрузкой, длительность.
**Действия:** тап по карточке → лист: дата/время · кнопки Открыть тренировку / Редактировать / Клонировать · «Детали сессии» · «Детали упражнений»: таблица Подход · Значение · Effort · ✓ · внизу «Удалить». Клонировать → форма «Внести задним числом» с предзаполнением.
**Внести задним числом (форма):** дата · effort общий · по упражнениям таблица подходов (значение по metric_type ±, effort, ✓), «Добавить подход», заметка к упражнению · заметки · Сохранить. Без ограничения глубины дат. Не участвует в каскаде.
**Свободная тренировка (форма):** дата · тип (список) · effort · длительность · заметки. Как Crimpd Cross-Training.
**Редактирование сессии из плана:** после сохранения → если есть последующие сессии того же `ProgramInclusion` → лист «Изменится план»: список «упражнение: было → станет» из `preview` · «Применить» / «Оставить как есть».
**Наше:** preview каскада, фильтр «по курсу».

### 10.7 Сессия — пред-экран

**Видно:** название (курс/упражнение) · разминка (текст, позже видео) · цели: по блокам «3×15 + макс» с текущими target'ами · для процентной стратегии — «90% от твоего 2ПМ (48 кг) = 43 кг» · «Начать».
**Состояния:** rest_policy жёсткая, отдых не прошёл → экран показывает «Отдых до <дата>», «Начать» нет · мягкая → баннер «Ты тренировал это вчера. Отдых важен для прогресса» + «Всё равно начать» · нет target'ов (не пройден нужный тест для процентной стратегии) → «Сначала пройди тест <название>» с кнопкой — **это то самое «нет тупиков»: кнопка всегда ведёт к действию, которое может завершиться.**

### 10.8 Сессия — live (= Crimpd timer)

**Видно:** название упражнения · крупный таймер (цвет фазы: оранжевый «Приготовься», зелёный «Пошёл», синий «Отдых») · «Подход 2/4 · Повтор 1/1» · панель лога (раскрывается автоматически в фазе отдыха): вкладки подходов, значение ± (по metric_type), «Цель: 15», слайдер «Как тяжело?» 5 сегментов, «+ Заметка» · транспорт: ‹подход ‹повтор ▶/⏸ повтор› подход› · сверху «свернуть» и «завершить».
**Логика:** таймер считает от серверного `ends_at` фазы (сервер уже умеет) · при возврате из фона — пересчёт от `ends_at`, никакого «замершего» таймера · Wake Lock через `nosleep.js` включён на всё время сессии · звук конца фазы планируется заранее через Web Audio · подходы пишутся локально (IndexedDB) и уходят батчем; индикатор «не синхронизировано» при отсутствии сети.
**Комплекс:** упражнения идут подряд как отдельные шаги, у каждого свой отдых; закрытие каждого — отдельный `PlanItem`.
**Прерывание:** «Завершить» → «Закончить сессию» (что сделано — зачтено, остальное остаётся в плане) / «Продолжить». Закрытие Mini App без завершения → при следующем входе баннер «Есть незавершённая тренировка (12 мин назад)» → Продолжить / Завершить.

### 10.9 Сессия — итог

**Видно:** «Сделано» с галочками по упражнениям · план vs факт по подходам · для шаговой стратегии: «Следующая цель: 16 (было 15)» · монеты: «+10 монет» · новое достижение, если есть · стрик · «Заметка к тренировке» · «Закрыть».
**Наше:** всё, кроме списка сделанного.

### 10.10 Аналитика (= Crimpd Analytics)

Как сейчас (свои SVG) + переключатель периода 1 мес / 3 мес / свой · «По категориям» (кольцо) · «По неделям» (столбики, цвет = категория) · сводная таблица категория → подкатегория (тренировки, минуты) · «Скачать CSV». Графики прогрессии подтягиваний остаются как есть (Эпли, по резине — только внутри одной резины).

### 10.11 Профиль (= Crimpd Profile)

Имя, возраст, пол · рост/вес · **Нормативы** ГТО/ВСФ (как сейчас) · **Тесты**: карточки AssessmentProtocol с датой последнего, ключевой метрикой и мини-трендом; пустое состояние «Тест не пройден» + кнопка · **Монеты и достижения** (как сейчас) · **Лидерборд** (как сейчас) · **Подписка** · **Напоминания** (модель: по расписанию / по готовности — как сейчас, но на уровне плана) · Настройки (единицы, часовой пояс, тема).

### 10.12 Библиотека и конструктор (= Crimpd Create Workout)

«Создать комплекс»: название → «Добавить упражнение» → поиск по библиотеке (`free-exercise-db` как seed + свои) или «Создать упражнение: <имя>» с выбором `metric_type` → для каждого: подходы ±, отдых между подходами, повторы ±, таймер повтора вкл/выкл, длительность → категория/подкатегория → сохранить в «Мои комплексы». Далее добавляется в план как строка.

## 11. Машина состояний сессии

```
IDLE ──(план есть, отдых прошёл)──► READY ──«Начать»──► ACTIVE
IDLE ──(жёсткая rest_policy, рано)──► BLOCKED (кнопки нет, показана дата)
IDLE ──(мягкая rest_policy, рано)──► WARNED ──«Всё равно»──► ACTIVE
IDLE ──(нужен тест, не пройден)──► NEEDS_ASSESSMENT ──► экран теста

ACTIVE: цикл фаз get_ready → go → rest, каждая с серверным ends_at
ACTIVE ──«свернуть»──► ACTIVE (таймер от ends_at продолжает)
ACTIVE ──пауза──► PAUSED ──► ACTIVE
ACTIVE ──«Завершить: закончить»──► COMPLETED → итог → preview/apply прогрессии
ACTIVE ──закрыл приложение──► ACTIVE (draft в IndexedDB) → баннер при входе
COMPLETED: все закрытые PlanItem помечены, монеты начислены, триггеры достижений
```

Сервер — источник правды по `ends_at`; клиент — по введённым значениям до синхронизации.

## 12. Контракт `/api/v2` для волн 5–6

*Дополняет CRUD волны 3. Имена — предложение; агент сверяет с существующими роутами и **не дублирует** то, что уже есть.*

**Сессия**
- `POST /sessions` — старт. Тело: `{client_session_id: uuid, plan_item_ids: [...]}`. Идемпотентно по `client_session_id`. Ответ: `session_id`, структура блоков/подходов с target'ами, `phase: {name, ends_at}`.
- `POST /sessions/{id}/phase/next` — перейти к следующей фазе/подходу. Ответ: новая фаза с `ends_at`. Идемпотентно по `{expected_phase_index}`.
- `POST /sessions/{id}/sets:batch` — батч подходов: `[{set_index, exercise_id, value, effort, note, client_ts}]`. Идемпотентно по `(session_id, set_index)`; повтор — upsert. Это основной офлайн-эндпоинт.
- `POST /sessions/{id}/complete` — завершить. Тело: `{abandoned: bool}`. Ответ: итог + `progression_preview`.
- `GET /sessions/active` — незавершённая сессия для баннера.

**Прогрессия**
- `POST /program-inclusions/{id}/progression/preview` — тело: `{edited_session_id}` → `[{plan_item_id, exercise, before, after}]`.
- `POST /program-inclusions/{id}/progression/apply` — то же тело, применяет.

**План**
- `GET /plan/current` — план с неделями, `PlanItem` (источник, день, кол-во, сделано), курсами.
- `PATCH /plan-items/{id}` — `{weekday|null, qty_by_week}`.
- `POST /plan/items` — добавить строку (упражнение или комплекс → раскладывается).
- `GET /plan/weeks/{n}/summary` — план vs факт недели.

**Курсы**
- `GET /programs`, `GET /programs/{id}` — каталог, карточка с расписанием.
- `POST /programs/{id}/inclusion/preview-conflicts` → пары пересечений.
- `POST /programs/{id}/inclusion` — тело: `{conflict_resolutions: [...]}` → создаёт снимок и `PlanItem`.
- `DELETE /program-inclusions/{id}` — удалить курс из плана (история остаётся).

**Журнал**
- `POST /sessions/backdated`, `POST /sessions/freeform`, `POST /sessions/{id}/clone` — формы 10.6.
- `GET /logbook?month=` — дни с точками + карточки.

**Тесты**
- `GET /assessments`, `POST /assessments/{protocol_id}/results` — результат теста; для процентной стратегии это вход.

**Офлайн-правило для всех POST:** клиентский `client_*_id`/индекс в теле; сервер возвращает 200 и тот же результат на повтор. Клиент — `@tanstack/react-query` с `persistQueryClient` (IndexedDB через `idb-keyval`), мутации в очереди при `onlineManager.isOnline() === false`.
