# Шаблон постановки worker-задачи

Orchestration hardening, 2026-09-20 (issue #188) — после зависшего 19-минутного
прогона (136 turns, $7.37, 14 permission denials на одну задачу). Правила
ниже — не пожелание, обязательная часть текста каждого worker-issue.

## 1. Base SHA gate (уже было, не отменяется)

```
EXPECTED_BASE_SHA=<BATCH_BASE_SHA>
```

Первым действием worker обязан вывести `EXPECTED BASE SHA` / `ACTUAL BASE SHA` /
`CURRENT BRANCH` / `BASE VERIFIED: YES/NO`. При NO — STOP, без кода.

## 2. Progress-чекпоинты

После каждого крупного milestone (не после каждого файла — после смыслового
куска работы: «бэкенд готов», «фронтенд экрана готов», «тесты написаны»)
worker обновляет статус — коротким сообщением в issue или явной пометкой в
финальном отчёте, если промежуточные комментарии дороги. Цель — не
догадываться по тишине в логе, жив процесс или завис (см. issue #188,
инцидент с worker B: 8+ минут без новых строк оказались не зависанием, а
одним долгим tool-call — но узнать это со стороны было нечем).

## 3. Лимит попыток при permission denial

**Максимум 2 попытки** одного и того же заблокированного действия. После
второго отказа — не повторять в третий раз, а описать в финальном отчёте
(см. п.4) и продолжить работу без этого действия, либо STOP, если без него
задача невыполнима.

## 4. Обязательная секция в финальном отчёте

```
PERMISSION DENIALS:
- <команда/tool>: зачем была нужна → как обошёлся без неё (или что не смог сделать)
```

Даже если отказов не было — писать «PERMISSION DENIALS: нет».

## 5. Дробление крупных задач

Если задача оценивается **дольше ~10–15 минут** — не превращать в один
огромный worker-прогон. Дробить на этапе постановки (до запуска, не
надеяться, что агент сам остановится на середине):
- отдельный issue на backend/schema и отдельный на frontend/UI, если они
  разумно разделимы (пример — Worker B 2026-09-20: PlanWeek API + Dashboard
  UI в одной задаче потребовали 136 turns);
- либо один issue, но с явным чекпоинтом внутри текста («сначала сделай X,
  закоммить, потом Y» — не «сделай X и Y одним заходом»).

## Что не входит в этот шаблон

`timeout-minutes: 30` на уровне job — это защита workflow, не текста
задачи, см. `.github/workflows/claude.yml`.
