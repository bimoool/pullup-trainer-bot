# Карта кода: graphify вместо grep

`graphifyy` уже в dev-зависимостях (`pip install -e ".[dev]"`), команда — `graphify`.
Граф вызовов/импортов по AST. Без LLM, детерминированно, 10–20 секунд на весь репозиторий.

## Правило

Прежде чем делать три и более `grep`/`Glob` подряд в поисках связей — построй граф и спроси его.
Серия grep'ов по этому репозиторию стоит дороже и находит хуже: логика размазана по слоям
`app/domain/` → `app/db/repositories/` → `app/bot/handlers/` + `app/web/`, имена совпадают
частично, а половина связей идёт через словари состояния, а не прямые импорты.

## Команды

```bash
graphify update .                        # построить/обновить граф (инкрементально)
graphify query "вопрос своими словами"   # BFS по графу, находит релевантные узлы
graphify explain "имя_функции_или_файла" # что это и с чем связано
graphify path "A" "B" --undirected       # как A и B связаны между собой
```

## Когда НЕ нужен

Точечная правка внутри одного известного файла; опечатка; правка текста.

## Замечания

- `graphify-out/` — сгенерированное, в `.gitignore`, не коммитить.
- Реальный пример, ради которого это заведено: `is_heavy` блока Б →
  `suggest_heavy_weight_kg`/`resolve_heavy_weight_growth` (`app/domain/progression.py`) →
  `_exclude_heavy_entries`/`recalculate_cascade` (`app/db/repositories/workouts.py`) →
  `epley_progress` (`app/domain/reports.py`). Руками это серия из 6+ grep, графом — один запрос.
