# Telegram Mini App: правила

Работаем через `@telegram-apps/sdk` и `@telegram-apps/telegram-ui` — они уже в
проекте. Кнопка «назад», тема, viewport — **только через SDK**, не руками.

## initData

Авторизация — `initDataRaw`, проверяется на сервере. Вне Telegram его нет: при
открытии страницы в обычном браузере приложение обязано показать понятный
текст, а не белый экран и не стек ошибок.

## Компоненты кита

`Input`, `Select` и подобные из `@telegram-apps/telegram-ui` рассчитаны на
использование **внутри `Section`**. Без обёртки они рендерятся без оформления:
поле работает, но не видно ни подписи, ни рамки — пользователь не понимает, что
там надо что-то ввести. Это уже был реальный баг на онбординге.

Подпись поля — через проп `header`, а не отдельным текстом рядом.

## Кнопка «назад» и навигация

Аппаратная и телеграмная кнопка «назад» обрабатывается через SDK. Экран, с
которого нельзя вернуться, — ошибка. При переходе между вкладками нижнего меню
кнопка «назад» не должна закрывать приложение неожиданно.

## Тема и safe area

Цвета берутся из темы Telegram, не хардкодятся: у пользователя может быть
светлая или тёмная. Нижнее меню и фиксированные элементы учитывают safe area —
иначе на телефонах с вырезами элементы уезжают под системные полосы.

## Чего не делать

- Не использовать `window.open` для внешних ссылок — только методы SDK.
- Не полагаться на размер окна: viewport в Mini App меняется при открытии
  клавиатуры и разворачивании.
- Не проверять экраны только глазами в Telegram: для этого есть Playwright и
  скилл `webapp-testing`.
