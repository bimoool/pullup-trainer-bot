# Что мы строим

Турникмэн превращается из бота под одни подтягивания в **многокурсовую
тренировочную платформу**. Полная архитектура — `docs/architecture-multicourse.md`
(доменная модель, экраны, риски, журнал решений, волны 0-11). Читай её,
а не догадывайся.

# Референс — Crimpd

Функциональный образец — приложение **Crimpd**. Когда неясно, как должен
вести себя экран, ответ «как в Crimpd». Дизайн делается отдельным заходом,
функциональная модель — уже зафиксирована.

Навигация Crimpd: **Home / Training Plans / Logbook / Analytics / Profile**.

- **Home** — каталог тренировок по категориям с поиском «что хочешь
  потренировать сегодня», карточки курсов с количеством тренировок внутри.
- **Training Plans** — вкладки In Progress / Upcoming / Completed, планы с
  датами начала и конца.
- **Logbook** — история по месяцам → неделям → дням; на каждом упражнении
  Intensity, Completion, Resistance, Time Under Tension, Est. Duration.
- Логирование посторонней активности — отдельная простая форма (дата, тип,
  усилие, длительность, заметки).

# Жёсткие продуктовые правила

1. **Стартовый экран — Dashboard, а не открытая тренировка.** Dashboard
   показывает единый план: что осталось на этой неделе (свободный пул +
   расставленное по дням), стрик, быстрый старт. Экран, который сразу
   открывается на конкретной тренировке — неверное поведение.
2. **Всё отталкивается от замера.** Если по результату замера нужен снаряд
   (резина или дополнительный вес) — сказать об этом сразу **после замера**,
   отдельным шагом, а не молча подставить и показать на первой тренировке.
3. **Для каждого экрана продумано пустое состояние.** Нельзя предлагать
   действие, которое гарантированно не может завершиться успехом.
4. **Один активный план**, в него подключается несколько программ. План
   бессрочный, курсы внутри — со своими сроками.
5. **Комплекс — единица планирования, но не зачёта.** Состояния «частично
   выполнен» не существует.
6. **Невыполненное за неделю сгорает**, прогрессия назад не откатывается;
   прошлая неделя открыта для внесения задним числом.
7. **Геймификация — часть модели с первого дня**, не примочка поверх.

# Чего не делать

- Не изобретать поведение экрана, когда есть референс — сверься с ним.
- Не заводить вторую систему идентичности: веб-версия авторизуется через
  Telegram Login Widget.
- Не использовать YouTube для видео техники — часть аудитории не откроет.
- Не планировать нативное приложение: веб-версия это PWA.
