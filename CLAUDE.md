# pullup-trainer-bot — обязательная точка входа для агентов

Репозиторий — **единственный канонический источник истины**, не история чата. Этот файл
короткий намеренно: он говорит, что прочитать и чего не нарушать. Подробности — в документах ниже.

## Гейт перед кодом (обязателен, по порядку)

1. **Состояние:** `git status`, ветка, `HEAD`, чистота дерева. Работа — только в своей ветке/
   worktree, не в `main`; ничего не деплоить, не форс-пушить, не мержить без явной просьбы.
2. **`docs/PROJECT_SPEC.md`** — принятое продуктовое поведение.
3. **`docs/IMPLEMENTATION_PLAN.md`** — что сделано, что дальше, как работать.
   Задача волн DOMAIN-V2 → сначала **`docs/domain/`** (целевой доменный контракт: Workout →
   Program → Plan → Live → TrainingSession → Journal/Analytics, миграция, journeys J1–J12).
4. **Релевантные skills** из `.claude/skills/` (`multi-program`, `migrations-safe`,
   `running-tests`, `offline-session`, `product-reference`, …).
5. **Реальный код** — читать перед правкой, не полагаться на память/описание.
6. **Конфликты и пробелы:** документы расходятся между собой, с кодом или продуктовое решение
   нигде не записано → **остановиться и спросить владельца**, не придумывать.

## Состояние задач и оркестрация

Текущее состояние — `docs/PROJECT_STATUS.md` (или закреплённый issue «Project Status»), задачи —
GitHub Issues с метками `status:*`. Чат/сессия одноразовы: всё нужное для продолжения — в GitHub
и запушенных ветках (`python scripts/orch.py resume`). Цикл planner → worker, лимит 5 задач,
правило чекпойнта commit → push → комментарий → статус: `docs/AGENT_EXECUTION_MODEL.md`
§ Orchestration, `docs/PLANNER_AGENT.md`, `docs/WORKER_AGENT.md`.

## Приоритет источников

`.specify/memory/constitution.md` > `docs/PROJECT_SPEC.md` > `docs/IMPLEMENTATION_PLAN.md` >
`docs/ENGINEERING_NOTES.md` / `docs/adr/*` / skills > код как факт > чат. Конфликт с конституцией
выигрывает конституция; нижестоящий документ затем исправляется.

## Нерушимое (кратко; полный текст — конституция и PROJECT_SPEC)

- `app/domain/` — чистая логика: без `aiogram`/`sqlalchemy`, `datetime.now()` только снаружи.
  Репозитории — единственные, кто трогает сессию БД; хендлеры/роуты тонкие.
- Определения `Complex` / `ComplexItem` / `Exercise` / `PlanItem` не удаляются и не портятся
  операциями над сессиями.
- **Удаление истории:** исторические/критичные для прогрессии записи не удаляются разрушающе,
  если это может нарушить прогрессию или историю. Завершённая пользовательская Builder-сессия
  удаляется жёстко **только** когда бэкенд доказал независимость от защищённой прогрессии
  (предикат безопасного удаления, `PROJECT_SPEC §3`); всё недоказанное — отказ.
- Публичные эндпоинты не привязывают объекты по произвольному id: видимость/владение проверяются,
  недоступное = 404 (`PROJECT_SPEC §5`).
- Миграции — только аддитивные и совместимые со старым кодом.
- Тест, закрывающий баг, доказывается откатом исправления. Тесты — реальный Postgres.
- Монеты v2 пока **не работают** (известный долг) — не утверждать обратное.

```bash
export DATABASE_URL="$TEST_DATABASE_URL"
pytest -q && ruff check app/ tests/ scripts/
(cd webapp-frontend && npm install && npm run build)   # tsc -b + vite build
```

## Живая документация

инцидент, ловушка → `docs/ENGINEERING_NOTES.md` (там же — бывшее содержимое этого файла: разделы,
на которые ссылаются комментарии кода «см. CLAUDE.md …», сохранены с теми же заголовками).
Изменился порядок работ/статус → `docs/IMPLEMENTATION_PLAN.md`.
